# 核心业务约束先锁定：
1、权限两层隔离：平台全局权限、门店私有权限，两套权限池互不通用
2、授权主体隔离：超级管理员只能管平台权限，无权插手任何门店内部人员权限；门店老板仅能管理自己本店权限，无权跨店、无权平台权限
3、数据天然隔离：门店订单、商品、员工数据按门店隔离，权限绑定门店维度
基于标准 RBAC 模型 + 租户域（门店）+ 分级授权 改造，完全贴合 SaaS 多门店点餐系统通用权限规范
# 一、整体权限架构思想（业内标准分层）
采用 RBAC-D 带数据域权限模型
基础：用户 → 角色 → 权限
扩展：增加权限域（全局域 / 门店域）、门店租户 ID
核心隔离规则
1、全局角色 / 权限：仅超管创建、分配、管理
2、门店角色 / 权限：仅本店店主创建、分配、管理
两类角色、权限不能交叉绑定、不能跨域授权

# 预设角色参考
1、全局角色：超级管理员、平台运营、平台审核
2、门店角色：店铺老板、收银员、后厨、服务员、库存管理员
3、普通用户客户

超级管理员

本店员工（收银/后厨/服务员）
    ↓
操作本店点餐、收银、订单、商品
