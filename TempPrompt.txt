## Controller 层编写规范建议

### 1. 三层 Controller 包结构

```
controller/
├── {Module}Controller.java          ← 用户端（只读/公开）
├── manage/
│   └── {Module}ManageController.java ← 店主端（门店域操作）
└── sys/
    └── {Module}SysController.java    ← 超管端（全局域操作）
```

每个业务模块按**使用者角色**拆分为三个 Controller，而不是按功能类型拆分。

### 2. 路径命名规范

| 层级 | 路径模式 | 示例 |
|------|---------|------|
| 用户端 | `/api/{module}/` | `/api/store/list`, `/api/dish/{id}` |
| 店主端 | `/api/{module}/manage/` | `/api/store/manage/update`, `/api/dish/manage/add` |
| 超管端 | `/api/sys/{module}/` | `/api/sys/store/audit`, `/api/sys/user/list` |

### 3. 权限校验策略选择

```java
// 用户端：公开接口无需校验，个人操作用 @SaCheckLogin
@SaCheckLogin
@PostMapping("/update")

// 店主端：门店维度操作用 StoreAuthHelper
storeAuthHelper.checkStoreOwner(storeId);
storeAuthHelper.checkStorePermission(storeId, "dish:manage");

// 超管端：全局权限用 Sa-Token 注解
@SaCheckPermission("user:manage")
@SaCheckPermission("store:audit")
```

### 4. 编写新 Controller 的检查清单

- [ ] **明确使用者角色**：这个接口是给谁用的？用户/店主/超管？
- [ ] **放到正确的包**：用户端 → `controller/`，店主端 → `controller/manage/`，超管端 → `controller/sys/`
- [ ] **选择正确的权限校验方式**：
  - 公开只读 → 无校验
  - 登录即可 → `@SaCheckLogin`
  - 门店操作 → `StoreAuthHelper`
  - 全局管理 → `@SaCheckPermission`
- [ ] **域隔离**：门店域数据操作必须传 `storeId`，并通过 `StoreAuthHelper` 校验归属
- [ ] **不暴露敏感数据**：返回 UserData 时 `setPassword(null)`
- [ ] **写操作用 POST**：创建/更新/删除统一用 `@PostMapping`
