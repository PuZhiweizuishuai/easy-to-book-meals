## 修复扫码免登录下单校验异常 + 结算关联会员积分

### 问题根因
堂食扫码免登录下单时 `UserData` Bean Validation 校验失败：
- `phone` 上 `@NotBlank(message="电话不能为空")` —— 匿名顾客无手机号被拦截
- `nickname`/`password`/`email` 用了 `@Max`（仅适用数字字段），String 字段被强制转数字失败，报"昵称最长不超过50个字符"等
（注：上轮 createGuestUser 并未真正绕过 @NotBlank，故落库时由 Hibernate flush 触发校验报错）

### 后端改动
- `data/UserData.java`：phone 去掉 `@NotBlank`；password/nickname/email/phone 的 `@Max` 全改为 `@Size`（修正历史 bug）
- `data/OrderData.java`：新增 `contactPhone` 字段（结算联系电话）
- `service/UserDataService.java`：新增 `bindPhone(userId, phone)` 方法（匿名顾客结算时回填手机号，处理 unique 冲突）
- `service/OrderService.java`：注入 `MembershipService`；新增 `completeOrder(orderId, storeId, phone)` 方法
  - 完成 `transitionOrder(COMPLETED)` 后，若录入 phone：关联会员（手机号对应已注册用户则切换订单归属，否则回填到当前 guest 用户）+ 按 1元=1积分累积到 Membership
- `controller/manage/OrderManageController.java`：`/complete/{id}` 端点增加可选 `phone` 参数
- 编译验证：用 JDK 21（`C:\Program Files\Java\jdk-21.0.3`）+ Lombok 1.18.46 通过（系统 java 是 JDK 25，lombok 不兼容）

### 前端改动
- `OrderManagement.vue`：第 112 行"完成"按钮改为"结算完成"，打开结算弹窗
  - 弹窗显示订单号/下单人/应付金额，可输入顾客手机号（可选），实时预览本次积分
  - `confirmComplete` 调用 `/order/manage/complete/{id}?storeId=&phone=`，成功提示已累积积分
- 前端 npm run build 通过，已同步到 static 目录

### 关键点
- 项目 `<java.version>21</java.version>`，命令行编译须用 JDK 21，否则 Lombok 报 `TypeTag::UNKNOWN`
- 积分累积按 `payAmount` 向下取整（1元=1分，不足1元不计）
- Membership 按 (storeId, phone) 维度存，`addPoints` 自动 upsert

## 优化：扫码刷新展示已下单菜品 + 规格展示修复

### 问题 1：扫码下单刷新页面后展示已下单菜品
- 后端 `OrderService` 新增 `getGuestCurrentOrder(qrCodeKey)`：按二维码查餐桌→取 currentOrderId→返回未结算订单（待接单/已接单/制作中/已出餐），已结算/取消返回 null
- 后端 `OrderService` 新增 `addItemsToGuestOrder(orderId, qrCodeKey, dto)`：免登录加菜，校验订单餐桌的 qrCodeKey 匹配
- `OrderController` 新增 `/guest-current`（GET）和 `/guest-add-items/{id}`（POST）两个免登录端点
- 前端 `StoreMenuPage.vue`：扫码场景 onMounted 调用 `fetchGuestCurrentOrder`，展示"本桌订单"卡片（订单号/状态/菜品列表/规格/数量/合计）；`submitOrder` 智能分流——本桌有未结算订单时走 `guest-add-items` 自动加菜，否则走 `guest-create` 新建，新建后自动加载本桌订单展示

### 问题 2：订单详情规格展示成"大份/小份"
- 根因：`ProductSkuService.createSingleSku` 把整道菜所有规格值名称 Map 都赋给每个 SKU 的 specNames，前端 `Object.values().join('/')` 全显示
- 修复：`createSingleSku` 改为只缓存 combination 实际选中的规格值（如 {1:"大份"}）
- 历史数据迁移：新建 `runner/SpecNamesMigrationRunner`（ApplicationRunner，启动时幂等执行），按 SKU.specs 过滤 specNames；OrderItem 通过 skuId 关联 SKU.specs 过滤
