## 修复 KitchenView.vue 运行时 TDZ 错误

### 现象
进入后厨出餐页面报：
`Uncaught ReferenceError: Cannot access 'stopAutoRefresh' before initialization`
页面因 setup 抛错无法显示。

### 根因
原代码顺序：
```
onMounted(() => { ... startAutoRefresh() })   // 箭头函数，惰性求值，OK
watch(..., () => { ... fetchQueue() })        // 箭头函数，惰性求值，OK
onBeforeUnmount(stopAutoRefresh)              // 直接传变量，立即读取 → TDZ！
...
const stopAutoRefresh = () => { ... }          // 定义在下方
```
`onBeforeUnmount(stopAutoRefresh)` 在 setup 执行时立即读取 `stopAutoRefresh`
作为参数传入，但该 const 声明位于下方，处于暂时性死区（TDZ），
故抛 ReferenceError。`onMounted`/`watch` 内的引用都包在箭头函数里，
回调执行时声明已完成，不受影响。

### 修复
`FoodWeb/src/views/admin/KitchenView.vue`：重排 script setup 顺序，
把 `toggleAutoRefresh` / `startAutoRefresh` / `stopAutoRefresh` 函数声明
移到 `onMounted` / `watch` / `onBeforeUnmount` 生命周期注册之前。
统一"函数先定义、生命周期后注册"的写法，彻底避免 TDZ。

### 验证
- 前端 `npm run build` 通过，产物已同步到 `food/src/main/resources/static/`
  （新产物 `KitchenView-pk5PjfAj.js`）

### 教训
Vue 3 `<script setup>` 中注册生命周期钩子时，若直接把变量作参数传入
（如 `onBeforeUnmount(fn)`），会在 setup 执行时立即读取该变量；
必须确保对应声明已在前。包在箭头函数里（`onBeforeUnmount(() => fn())`）
可惰性求值，但函数声明前置更清晰。

## 后厨队列改为菜品维度扁平列表

### 背景
原 KitchenView 按订单分组展示菜品，加菜菜品聚在原订单块内，
后厨视线被订单边界割裂；且加菜不按其自身下单时间排序，易遗漏。

### 改动
**后端**
- `OrderService.kitchenQueue`：返回扁平 List<Map>，每条=单个菜品+所属订单信息
  - 字段：itemId/dishName/specNames/quantity/topImage/addedLater/itemCreateTime/waitedMinutes
    + orderId/orderNo/orderType/tableNumber/remark/contactPhone/status
  - 按 `OrderItem.createTime` 升序排序（加菜自然落到后面）
  - 等待时长以菜品 createTime 起算（接单后加菜从加菜时刻起算）
- `OrderManageController.kitchenQueue`：聚合字段调整
  - `items`（队列本体）/ `itemCount`（菜品总数）/ `maxWaitedMinutes`
  - 去掉 `orders`、`orderCount`、`pendingCount` 求和

**前端 `KitchenView.vue`**：模板重写
- 从订单卡片网格 → 扁平菜品行列表
- 每行：等待时长色块 | 菜品(名+数量+加菜/超时徽章+规格+备注) | 订单信息(桌号/类型/同单N道+订单号+电话) | 出餐按钮
- 等待时长按菜品 waitedMinutes 着色（绿/黄/红，超时 15min）
- 线上/外送订单(orderType≠0)且有 contactPhone 时显示电话
- 保留「同单全出」次按钮：仅当同订单还有 ≥2 道未出餐时显示，调 /serve-order/{id}
- 概览卡 3 项：待出餐菜品数 / 最长等待 / 超时菜品数

### 验证
- 后端 `mvn -DskipTests compile` 通过
- 前端 `npm run build` 通过，产物已同步到 static/
  （新产物 `KitchenView-x8fsdlYA.js`）

### 关键点
- 加菜菜品有独立 createTime，扁平排序下自然按"加菜时刻"排在原订单菜品之后
- 后厨视觉焦点从"订单"转到"下一道要做的菜"
- 同单全出保留批量能力，但不抢主操作位
