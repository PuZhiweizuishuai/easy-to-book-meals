# 点餐应用功能完善建议

> 基于对前后端代码的完整审查，整理出当前未完成或有缺陷的功能点及改进建议。
> 按优先级分级：**P0 严重缺陷** / **P1 核心缺失** / **P2 增强项**。

---

## P0 严重缺陷（建议尽快修复）

### 1. 支付状态完全未实现

- **现状**：`PayStatus` 枚举自身注释已写明"支付系统暂未对接"。`OrderData.payStatus` 创建时默认为 `0（未支付）`，且 **全代码库没有任何地方更新过该字段**，永远停在 0。
- **影响**：无法区分"已付/未付"，营业额统计（`storeStats` 用 `sumStoreRevenue`）实际把所有已完成订单都算作收入，到店收银无法核对。
- **建议**：
  - 短期：在"完成订单"时由店员手动标记支付状态（增加 `pay` 操作按钮），或顾客端增加"模拟支付"。
  - 长期：对接微信/支付宝支付，完成 `UNPAID → PAID` 的回调驱动流转，`PAID → REFUNDED` 的退款审批流。

### 2. 取消订单时餐桌状态流转错误

- **现状**：`OrderService.cancelOrderInternal` 与 `onOrderCompleted` 都调用 `releaseTable → clearCurrentOrder`，而 `clearCurrentOrder` 无条件把餐桌设为 `CLEANING（清理中）`。
- **影响**：顾客刚下单就取消（餐桌从未真正使用），餐桌却被标为"清理中"，必须人工改回"空闲"，浪费服务员操作。
- **建议**：`releaseTable` 增加参数区分"取消"与"完成"两种场景：
  - 取消（订单未真正就餐）→ 餐桌回到 `FREE（空闲）`
  - 完成（客人离席）→ 餐桌设为 `CLEANING（清理中）`

### 3. 库存显示 Bug（已修复）

- **现状**：`BaseFood.stock` 是管理员设置时的静态快照，下单只扣减 `ProductSku.stock`，菜品卡片展示的库存永不更新。
- **修复**：已在 `FoodService.findStoreMenu` 中聚合各启用 SKU 的实时库存覆盖展示字段（见本次改动）。

## P1 核心缺失功能

### 4. 桌牌二维码界面（已修复）

- **现状**：`TableInfo.vue` 原为空占位页（"此页面待开发"），店主无法生成/下载点餐二维码。
- **修复**：已实现完整 `TableInfo.vue`——生成扫码二维码、下载/打印桌牌、展示当前订单、重置二维码，并已部署到静态资源目录。

### 5. 餐桌区域位置写死（已修复）

- **现状**：`TableFormModal.vue` 区域 select 写死 5 个选项，无法新增。
- **修复**：改为 `input + datalist`，支持自由输入，并从已有餐桌聚合候选区域。

### 6. 餐桌"清理中→空闲"无自动流转

- **现状**：餐桌进入 `CLEANING` 后只能人工切换回 `FREE`，无超时自动复位。
- **建议**：增加定时任务（如清理中超过 10 分钟自动转空闲），或在服务员端提供"一键清理完成"快捷操作。

### 7. 会员积分未与订单打通

- **现状**：`MembershipService.addPoints` 方法已存在，但 `OrderService.onOrderCompleted`（订单完成）**没有调用它**，会员积分永远不会累加。
- **影响**：会员体系形同虚设，无消费积分沉淀。
- **建议**：订单完成时按 `payAmount` 计算积分（如 1 元 = 1 分）并调用 `addPoints`，同时记录积分流水。

### 8. 后厨小票 / 结账单打印

- **现状**：无任何打印能力。后厨接单需看屏幕，断网/高峰期易漏单。
- **建议**：
  - 接单时生成后厨小票（菜品、规格、数量、备注、桌号），接入小票打印机（ESC/POS 指令或网口打印机）。
  - 完成订单时打印结账单供顾客核对。

### 9. 订单加菜 / 改单

- **现状**：订单一旦创建即为快照，无法在制作过程中追加菜品（堂食常见的"再加一个菜"）。
- **建议**：支持对"已接单/制作中"订单追加 `OrderItem`，新增项独立扣减库存、独立计入金额。

### 10. 库存预警

- **现状**：库存到 0 才在顾客端显示"已售罄"，店家无提前预警。
- **建议**：SKU 库存低于阈值（如 5）时在 Dashboard 高亮提醒，支持配置每个 SKU 的预警线。

## P2 增强项

### 11. 实时通知（WebSocket）

- 订单目前靠手动刷新，建议接入 WebSocket/SSE，新订单、状态变更实时推送到后厨与服务员端。

### 12. 营业报表与图表

- Dashboard 仅有今日汇总数字，建议增加：近 7/30 天营业额折线图、菜品销量排行图、时段分布图，支持导出 Excel。

### 13. 每日库存重置

- 当前库存是永久总量，只减不增。餐饮场景常需"每日备货量"概念：建议增加 `dailyStock` 字段，每日营业前重置，独立于累计销量。

### 14. 呼叫服务员 / 买单请求

- 顾客端无法主动呼叫服务或请求结账，建议在餐桌详情页加"呼叫服务员""请求买单"按钮，推送到服务员端。

### 15. 优惠券 / 满减活动

- 目前仅 SKU 级折扣，无门店级优惠券、满减、新客立减等营销手段。

### 16. 多规格选库存的统一校验

- `BaseFood.stock` 与 `ProductSku.stock` 双库存概念容易混淆（本次 Bug 根因）。建议明确职责：菜品级仅作"是否上架/不限库存"开关，真实库存一律以 SKU 为准，移除冗余的菜品级库存字段。
